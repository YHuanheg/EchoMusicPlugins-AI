# 歌单导入增强 · playlist-importer

**版本 1.0.0** · 要求 EchoMusic `>= 2.3.2-beta.2` · MIT

把其他音乐软件的歌单导入到 EchoMusic。支持**链接**、**本地文件**与**粘贴文本**三种入口，
导入前先做**匹配预演**（每首给出候选与分数，可以人工改选），确认之后才写入你的酷狗云歌单。

---

## 它解决什么问题

EchoMusic 已经内置了「导入外部歌单」（侧边栏「新建 → 导入外部歌单」，支持链接与截图）。
但那套流程是**一键黑盒**：匹配过程不可见、低置信结果无法人工干预、不支持本地歌单文件、
失败清单也拿不出来。本插件补的就是这几块：

| 能力 | 宿主内置 | 本插件 |
| --- | --- | --- |
| 链接导入（7 个平台） | ✅ | ✅（可手动指定平台） |
| 截图 OCR 导入 | ✅ | ❌ |
| **本地歌单文件导入** | ❌ | ✅ JSON / CSV / TXT / M3U / M3U8 |
| **匹配预演 + 人工改选** | ❌（全自动，低置信只标记） | ✅ 每首列候选与分数，可改选 / 跳过 / 单条重试 |
| **批内去重 + 目标歌单已有检测** | 部分 | ✅ 可选开关 |
| **失败清单导出 / 只重试失败项** | ❌ | ✅ CSV / JSON |
| 任务中心进度与停止 | ✅ | ✅ |

> 两者的落点是同一个：EchoMusic 本地库没有歌单表，**「歌单」就是酷狗云端歌单**，
> 所以导入结果会出现在「音乐库 → 我创建的歌单」里，手机端酷狗也能看到。

## 怎么用

1. 侧边栏「插件 → 歌单导入增强」打开插件页。
2. **选择来源**（三个 tab 任选其一）：
   - **链接导入**：粘贴歌单链接。平台可以留「自动识别」，也可以手动指定
     （网易云 / QQ 音乐 / 酷我 / 酷狗 / Spotify / 汽水音乐）。点「读取歌单」。
   - **本地文件**：点选或拖入 `.json` / `.csv` / `.tsv` / `.txt` / `.m3u` / `.m3u8`。
     单文件上限 8 MB。
   - **粘贴文本**：每行一首，格式 `歌名 - 歌手`；也可以直接粘 CSV 或 JSON 内容。
3. **匹配预演**：点「匹配预演（N 首）」。逐首搜索酷狗并给出 top-N 候选与分数。
   这一步**不写任何数据**，可以随便试。过程中可以「停止匹配」。
4. **核对与改选**：表格每行的下拉里列出候选（带分数 / 歌手 / 时长），
   可以换成别的候选、选「（不导入）」或「跳过这首」；单行还能「重试」。
5. **选目标**：默认新建歌单（名称默认取原歌单名，撞名会提示）；
   也可以切到「导入到已有歌单」，从你的歌单列表里挑一个。
6. **开始导入**：按 50 首一批写入，任务中心会显示进度并能「停止」。
7. **结果**：汇总显示 导入成功 / 未导入 / 批内重复 / 目标已有 / 失败 / 耗时；
   可以「导出 CSV / JSON」留档，或点「只重试失败项」把失败的那几首再来一遍。

## 匹配是怎么打分的

最终分数是三个因子的加权和（权重可在设置里理解，目前固定）：

```
总分 = 标题相似度 × 0.55  +  歌手相似度 × 0.30  +  时长接近度 × 0.15
```

- **标题**：归一化（全角转半角、迭代剥括号、去 `feat.`/`伴奏`/`无损` 等噪声词、去标点空白、小写）
  之后算二元组 Dice 相似度；短标题被长标题包含且占比 ≥ 60% 时给 0.92 下限。
- **歌手**：按 `/ 、 , & ·` 与 `feat.` 拆成多人后取最佳配对；任一边未知时给**中性 0.5**（不是 0）。
- **时长**：差 3 秒内 1.0，8 秒内 0.85，15 秒内 0.55，30 秒内 0.2，再远 0。
  **两边任一时长未知时这一项不参与**，权重按剩余两项重新归一化
  —— 否则「导出的歌单没有时长」会把所有匹配都压到阈值以下。

档位：

| 档位 | 条件 | 行为 |
| --- | --- | --- |
| 已匹配 | 分数 ≥ 接受阈值（默认 0.72） | 直接导入 |
| 低置信 | 0.55 ≤ 分数 < 阈值 | **默认不导入**，需勾「包含低置信」或人工改选 |
| 未匹配 | 分数 < 0.55 | 不导入，原因写进表格 |

每首最多用 3 个关键词搜（`歌名 + 首位歌手` → `去括号歌名 + 首位歌手` → `只搜歌名`），
一旦某轮出现达到阈值的候选就提前收手，不再多搜。

## 重复歌曲怎么处理

三层，都可以在设置或页面上关：

1. **批内去重**（默认开）：同一首歌在来源歌单里出现多次时只导入一条。
   身份用**歌曲级 key**（`mixSongId`，缺失时退回 `hash`）而不是文件级 `hash` ——
   同一首歌常有多个音质对应的不同 hash，只按 hash 去重会出现「好几条一模一样的歌」。
2. **目标歌单已有检测**（默认开）：导入前先读一次目标歌单的 hash 列表
   （最多 4 页 × 300 首），已经有的直接跳过，不重复写。
3. **人工跳过**：任意一行都可以在下拉里选「跳过这首」。

被跳过的行都会在表格里给出**可读原因**：`手动跳过` /
`与第 N 首是同一首歌（批内重复）` / `目标歌单里已经有这首` /
`低置信（0.63），未勾选「包含低置信」` / `未匹配到足够相似的歌曲` / `搜索失败：<上游原文>`。

## 导入写到哪里

EchoMusic 本地库（`echomusic.sqlite`）只有 `app_kv` / `play_history` / `playback_queues` /
`queue_items` / `songs` 五张表，**没有本地歌单表** —— 所以落点必然是酷狗云端歌单，
走宿主内置的本地路由（宿主负责注入设备指纹与 cookie，插件不自己拼签名）：

| 动作 | 路由 | 上游 |
| --- | --- | --- |
| 列我的歌单 | `GET /user/playlist` | `/v7/get_all_list` |
| 新建歌单 | `POST /playlist/add` | `/cloudlist.service/v5/add_list` |
| 加歌 | `POST /playlist/tracks/add` | `/cloudlist.service/v6/add_song` |
| 读歌单歌曲（去重用） | `GET /playlist/track/all` / `/playlist/track/all/new` | `get_other_list_file_nofilt` |
| 搜索歌曲 | `GET /search`（`type=song`） | `/v2/search/song` |

加歌时 `data` 参数是 `歌名|hash|albumId|mixSongId` 用逗号拼接的**复合串**，
所以歌名里的 `,` 与 `|` 会被替换成空格（否则一首歌的名字会把后面所有字段错位）。

**导入需要登录。** 没有检测到登录态时会直接拒绝并提示，不会静默失败。

## 出错了怎么办

- **「本次请求需要验证」**：这是酷狗风控。插件已内置兜底 —— 会唤起宿主的验证弹窗，
  通过后自动重试一次，并且**一整轮只弹一次**（不会每个关键词/每首都弹）。
  点击取消则这一批按失败上报，不会假装成功。
- **部分失败**：表格里失败行是红底并带原因；「导出结果」可以把完整清单存成 CSV / JSON；
  「只重试失败项」会把已成功的标记为跳过，只重跑失败的那几首。
- **显示「未知歌曲 - 未知歌手」**：说明来源格式里的字段名没被认出来。
  点「复制诊断」把快照贴给开发者 —— 里面有**上游原始键名与截断 JSON**，
  拿到就能精确校正（这是唯一可行的校准手段：带登录态的载荷只能在插件运行时拿到）。
- **页面上的「诊断」卡片**包含：入口与平台、歌单概览与未识别条数、原始键名、
  匹配统计与阈值、目标、选项、本地路由调用统计、环境探测、最近的上游错误。排查问题时先看它。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 匹配接受阈值 | 0.72 | ≥ 此值直接导入；0.55~此值为低置信 |
| 每首候选数 | 6 | 预演表下拉里最多列几个备选 |
| 搜索并发 | 2 | 本地路由在主进程是串行化的，开太高只会互相排队 |
| 搜索间隔 | 220 ms | 同一并发槽内两次搜索之间的间隔，防上游限流 |
| 临时失败重试间隔 | 700 ms | 只对网络层失败（`ECONNRESET` / `502 + error_code=0`）重试一次 |
| 加歌批大小 | 50 | 单次 `/playlist/tracks/add` 最多几首（上游模块的上限就是 50） |
| 加歌批间隔 | 400 ms | 批次之间的间隔 |
| 已有歌曲检查页数 | 4 | 去重时最多翻几页（每页 300 首） |
| 预演表渲染上限 | 60 | 超过就折叠，避免一次渲染几百行卡顿 |
| 包含低置信 / 跳过目标已有 / 批内去重 | 关 / 开 / 开 | 三个快捷开关，页面与设置面板联动 |

## 能力声明（为什么需要）

| 能力 | 为什么 |
| --- | --- |
| `unrestrictedNetwork` | 链接导入要直连网易云 / QQ 音乐等公开接口。少了这项，渲染进程的请求会被 CORS 拦掉，表现为"连不上"，是**假阴性**。本地文件与粘贴文本不联网。 |
| `kugouVerification` | 搜索与写歌单都走宿主本地路由，必须能唤起宿主的安全验证弹窗（否则用户侧表现为「每一首都失败：本次请求需要验证」）。 |

**刻意没有申请 `localFiles`**：读取本地歌单文件走的是 `<input type="file">` + `File.text()`，
与宿主自己导入截图用的同一条路，不需要文件系统能力。

## 已知边界

- **依赖外部平台页面结构的两个来源最脆弱**：Spotify 与汽水音乐是靠页面里内嵌的 JSON。
  平台改版会直接失效，插件会给「页面结构可能已变更」的明确文案而不是静默出错。
  遇到这种情况先改用「导出文件导入」——那条路不依赖任何外部接口。
- **酷我接口的分页上限是 50 页 × 100 首**，超大的歌单会被截断（会在曲目数上体现出来）。
- **本地文件导入不做时长校验**：TXT / CSV 里没有时长时，时长项不参与打分。
- 预览最多渲染 60 行（可调），但**匹配与导入仍然覆盖全部曲目** —— 折叠的只是渲染。

## 测试

```bash
node tests/playlist-importer.smoke.mjs    # 无头集成：505 条断言
node tests/playlist-importer.mutate.mjs   # 变异：48 个变异点必须全部被抓到
node tests/playlist-importer.live.mjs     # 真实网络：打真实网易云 / QQ 音乐 / 酷我，验证归一化
```

环境变量：`PI_PLUGIN_ENTRY` / `PI_CSS_ENTRY` 指向改动副本，`PI_REPORT_FILE` 改报告落点。

真实网络冒烟（2026-10-01 实测）：

```
· 网易云    ✓ 200 首   样例「明知故犯 - Max李玄」166s
· QQ 音乐   ✓  30 首   样例「虚拟 - 陈粒」240s
· 酷我      ✓ 337 首   样例「我和我的祖国 - 肖战」232s
归一化质量断言：26 通过 / 0 失败
```

它守的是**夹具证明不了**的那件事：真实响应能不能被归一化成可用的外部曲目
（没有「未知歌曲」、没有 `[object Object]` 泄漏、没有把毫秒当时长）。
走宿主本地路由的来源（酷狗自己、以及所有写入操作）在 Node 里连不上，只能在真机验证。
