# 概念版每日领VIP

每天自动领取酷狗概念版畅听 VIP：**听歌领取 + 广告领取 + 天天签到领取**，可选领取后自动升级概念版 VIP。
入口在软件顶部 ⭐（与「自动组队领VIP」同一工具栏区域）。

- 插件名：概念版每日领VIP
- 插件 id：`kugou-daily-vip`
- 版本：1.1.0
- 作者：YHuanheg
- 依赖：EchoMusic `>=2.3.2-beta.2`（需宿主已内置酷狗接口通道）
- 能力声明：`unrestrictedNetwork`（实际未使用原生网络）、`kugouVerification`（用于处理账号安全验证）

> 本插件不会把任何数据发往第三方服务器。所有请求都经宿主 IPC 打到 **本机内置的酷狗接口服务**，
> 由宿主完成签名（概念版 lite 盐值）、设备指纹与加密。插件只做编排与展示。

## 领取链路

每一个步骤都是幂等的——重复调用只会拿到「今日已领取」，不会重复计数。

| # | 步骤 | 接口（宿主内置路由） | 说明 |
|---|------|---------------------|------|
| ① | GUARD | `GET /user/detail` | 校验登录态；token 失效（`error_code` 20018/51002）即中止 |
| ② | RECORD | `GET /youth/month/vip/record` | 本月领取记录，只读展示 |
| ③ | LISTEN | `GET /youth/listen/song` | 听歌领取 **1 天**；`130012` = 今日已领取 |
| ④ | AD | `GET /youth/vip` ×N | 广告领取，**每次 1 天**，默认最多 8 次、间隔 30s；`30002` = 次数已用光 |
| ⑤ | DAYVIP | `GET /youth/day/vip?receive_day=…` | 天天签到领取 **1 天**；`131001` = 今日已领取 |
| ⑥ | UPGRADE | `GET /youth/day/vip/upgrade` | 领取后升级概念版 VIP（可选，默认关；无额度时按中性提示处理） |
| ⑦ | VERIFY | `GET /user/vip/detail` | 读取 VIP 到期时间（按业务线挑 `svip`，见下） |
| ⑧ | PERSIST | — | 写入当日记录 + 领取历史，驱动跨天补领 |

默认配置下一次完整领取约 **1 天（听歌）+ 最多 8 天（广告）+ 1 天（签到）**，
广告步骤因为要拉开 30s 间隔，整轮最长约 3.5 分钟，可随时点「停止」中断。

### 广告领取的倒计时（1.1.0 新增）

广告是整轮里最慢的一步（8 次 × 30s ≈ 3.5 分钟）。为了让这段时间**可见、可控**，
面板会在等待期间渲染一条倒计时进度：

```
广告领取中 · 已得 2 天，等待第 3/8 次              24s
████████████░░░░░░░░░░░░░░░░
本轮共 8 次 · 每 30s 一次 · 可随时点「停止」
```

- 秒数每 **500ms** 刷新一次，进度条按已等待比例增长。
- 同时写入顶栏状态（`广告领取中 · 已得 2 天 · 等待 24s（第 3/8 次）`）与广告步骤行。
- 等待过程可中断：点「停止」立刻结束，不会等满 30s。
- **1.1.0 的节奏修正**：起手就是「发请求 → 立刻开始倒计时 → 倒计时结束发下一次」。
  旧实现是「发请求 → 阻塞等 30s → 再发」，最后多白等一个间隔（整轮凭空多 30s）。

## 每日自动领取

- **默认开启**。软件运行期间每 30s 做一次「北京日期是否变了」的本地判断（不发请求）。
- 真正跨天后自动补领一次；完成（无失败项）后写 `lastDoneDate`，当天不再重复。
- 启动后 6 秒、登录后 4 秒各做一次补领检查（若当天已完成则跳过）。
- 中止或失败时**不写** `lastDoneDate`，下一轮会继续重试，不会出现「失败一次整天不再领」。

## 面板说明

点顶部 ⭐ 打开面板：

- **状态卡**：账号昵称 / UID、VIP 到期时间（含其它权益到期）、本月记录条数与已领取日期、北京日期。
- **今日领取**：四个步骤各自的实时状态（`✓` 成功 / `•` 已领 / `!` 失败 / `…` 进行中 / `—` 已关闭/中性），广告等待时插入倒计时进度条。
- **一键领取今日 VIP**：手动立即领取；**停止**：中断正在跑的广告循环。
- **设置**：9 项，改完立即落盘（见下）。
- **领取记录**：最近 7 天的领取摘要与到期时间。
- **复制诊断**：把账号、各步骤结果、原始响应 JSON 一次性拷进剪贴板，反馈问题直接贴上来即可。

> 打开面板只做**只读刷新**（3 个查询），不会触发领取。这是刻意的设计——否则点一下图标就要等 3 分钟广告流程。

## 设置项

| 设置 | 默认 | 说明 |
|------|------|------|
| 每日自动领取 | 开 | 跨天自动补领 |
| 听歌领取（1 天） | 开 | 关闭后不发 `/youth/listen/song` |
| 广告领取（每次 1 天） | 开 | 关闭后不发 `/youth/vip` |
| 广告领取次数上限 | 8 | 1~8，超出自动钳制 |
| 广告领取间隔 | 30 秒 | 0~120 秒，过短可能触发风控 |
| 天天签到领取（1 天） | 开 | 即「天天签到领VIP」活动 |
| 签到日期形态 | 自动 | `receive_day` 传「日号」还是「完整日期」，见下 |
| 领取后自动升级概念版 VIP | 关 | 关闭时不会调用升级接口 |
| 完成时弹提示 | 开 | 用 toast 汇报结果 |

### 关于「签到日期形态」

`/youth/v1/recharge/receive_vip_listen_song` 的 `receive_day` 参数官方没有公开文档，
社区实现里「当日日号」（如 `19`）与「完整日期」（如 `2026-09-19`）两种说法都有。

插件默认走**自校准**：先按「日号」试，若返回错误信息里出现「日期」字样就换成「完整日期」重试一次，
并把成功的那种记下来（`ctx.storage.receiveDayFormat`）供后续直接使用。也可以手动锁定形态。

> 已知坑：早期实现把 UTC 日期当 `receive_day` 传，会收到「日期不能小于今天」——
> 本插件一律用 **北京时间**（`getTimezoneOffset()` 换算），不受系统时区影响。

## 错误码对照

| error_code | 含义 | 插件行为 |
|-----------|------|---------|
| `status: 1` | 成功 | 记成功 |
| 130012 | 听歌今日已领取 | 记「已领取」，不报错 |
| 131001 | 签到今日已领取 | 记「已领取」，不报错 |
| 30002 | 广告次数已用光 | 立即停止广告循环（算中性结果，不算失败） |
| 「无法升级奖励」类 | 升级无额度 / 活动期已过 | 升级记为**中性**（`—`），不拖累整轮状态 |
| 20018 / 51002 | 未登录 / token 失效 | 中止并提示重新登录，不写 `lastDoneDate` |
| 20028 | 账号风控 | 触发宿主安全验证弹窗，通过后自动重试一次 |
| 其他 | 未知 | 保留原始响应，可在「复制诊断」里看到 |

> 「中性结果」的判定不只看错误码，也看话术：命中
> `已用光 / 已领完 / 已达到上限 / 无法升级 / 已是最新 / 暂无可领取` 等描述时，
> 一律按「今天本来就没有了」处理——这类情况重试也没用，更不该让用户以为插件坏了。

## 真机响应结构校正（1.1.0）

1.0.0 在真实账号上跑过一轮后，发现三处和文档/直觉不一致的地方，1.1.0 已修：

| # | 现象 | 真实结构 | 修法 |
|---|------|---------|------|
| 1 | 面板显示「本月已领取日号: -」 | `data.list[].day` 是**完整日期字符串** `"2026-06-20"`，不是日号 | `Number("2026-06-20")` → `NaN` → 全被过滤。改为保留完整日期（兼容时间戳/纯日号），显示成 `已领 3 天：06-20,06-21,07-01` |
| 2 | VIP 到期「恰好正确但语义不明」 | `data.busi_vip` 是**数组**，`svip`（畅听，09-23）与 `tvip`（听书，10-05）并存，且顶层 `data.vip_end_time` 是**空串** | 旧实现靠深度优先「碰巧」抓到第一条。改为显式按 `product_type` 打分挑 `svip`/concept，`tvip` 作为「其它权益」单独展示 |
| 3 | 误报「部分失败（升级），听歌(已领)，签到(已领)」 | 升级接口答 `无法升级奖励`（活动侧常态拒绝） | 升级是可选增强项，失败不该拖累整轮。改为中性态：整轮显示 `今日已领取：听歌(已领)，签到(已领)（本次无可升级额度）`，并且**算作完成**可写 `lastDoneDate` |

> 另外：`error_msg` 字段名各接口不统一，归一化时已补上
> `err_msg` / `error_message` / `message` / `error` 等变体。

## 账号安全验证

宿主原生认证包装器不做验证码兜底，因此插件自己处理：请求响应里若带 `ssaCode` / `eventId`
（或 `status: 0` 的失败且带 `eventId`），就调用 `ctx.kugouVerification.request(eventId)`
唤起宿主的验证弹窗，验证通过后**原请求重试一次**。
验证不通过时提示「账号需要安全验证，请在弹窗中完成验证后重试」。

## 实现要点（给后续维护者）

- 宿主对内暴露的是 **KuGouMusicApi 本地服务**（`resources/server/module/*.js`），
  路由规则是「模块文件名去掉 `.js` 后把 `_` 换成 `/`」：
  `youth_listen_song.js → /youth/listen/song`、`youth_day_vip.js → /youth/day/vip`。
  要看某个路由的参数，直接读 `resources/server/module/` 下对应文件即可，不用猜。
- 插件走 `ctx.electron.api.request` 这条 IPC，宿主会把 `headers.Authorization`
  按 `k=v; k=v` 解析成 cookie 注入本地服务，所以鉴权只需拼 `token` / `userid`（`dfid`/`t1` 有则带上）。
- 宿主 `api:request` 处理器**不看 HTTP 方法**（方法由服务端模块自己决定），
  所以插件一律用 `GET`，不要让方法名误导你。
- `deepFind` 只对外开放 `(obj, keys)` 两个参数，递归深度是内部状态。
  （1.0.0 开发期曾把 fallback 传成第三个参数，导致深度参数被字符串污染、
  深层字段永远查不到——这类 bug 静态检查抓不到，靠无头集成测试才发现。）

### 测试侧踩过的坑（给后续维护者）

- **测试用的 `openPanelFromToolbar()` 返回的是刷新前的快照**。面板必须在这之后
  用 `currentPanel()` 重新取一次，否则永远读到「未登录 / 读取失败」。
- **给源码打补丁注入快进时钟时，锚点必须唯一**。早期用
  `/}; \n today.adClaimed = r.claimed;/` 这种宽松正则，把测试文件自己 mock 里的同形代码也替换掉了，
  导致 `vipDetail` mock 被破坏、断言集体失败且极难定位。
- **`deepFind` 只对外暴露 `(obj, keys)` 两个参数**。开发期曾把 fallback 传成第三个参数，
  深度参数被字符串污染（`""→"1"→"11"`），深层字段永远查不到——静态检查抓不到，靠这里的集成测试才发现。
