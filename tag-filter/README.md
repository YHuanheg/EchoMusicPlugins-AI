# 插件标签筛选（`tag-filter`）

> 当前版本 **1.0.0**

给 EchoMusic 的「设置 → 插件」面板加一条**标签筛选条**：把面板里所有插件的标签自动聚合出来，
点一个或多个标签即实时过滤卡片列表，「清除筛选」回到完整列表，没有匹配时给出友好的空状态。

不用配任何东西 —— 装上、启用，回到插件管理页就能看到。

## 一、它长什么样

```
设置 → 插件
┌──────────────────────────────────────────────────────────────────────┐
│  [ 搜索框 ]        [ 来源 ▾ ]                  [ 刷新 ]              │   ← 宿主原有工具条
│  已安装插件                                     共 22 个 · 18/22 个已启用
│                                                                      │
│  按标签筛选  ⬤kugou 2  ⬤lyrics 5  ⬤player 3  ⬤浮窗 4 …   [任一|全部] [清除筛选]  │   ← 本插件注入
│  显示 5 / 22 · 已选 1 个标签 · 隐藏 17 个                             │
│                                                                      │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐                        │
│  │ plugin-card│ │ plugin-card│ │ plugin-card│   ← 不匹配的卡片被隐藏   │
│  └────────────┘ └────────────┘ └────────────┘                        │
└──────────────────────────────────────────────────────────────────────┘
```

标签就是从**卡片上宿主自己渲染的那排标签**读出来的，所以：

- 「已安装」与「在线插件」两个视图都能用，标签体系与宿主完全一致；
- 宿主自己的搜索框与来源筛选照常工作，本插件在**它们筛完的结果之上**再按标签收敛；
- 标签上的数字 = 当前视图里带这个标签的插件数（不会随你选了什么而跳动）。

## 二、功能

| 功能 | 说明 |
| --- | --- |
| **自动聚合标签** | 自动读取面板中所有插件卡片上的标签，去重、按出现次数排序后展示为可点的 chip |
| **多选实时过滤** | 点 chip 立即过滤，不需要确认；再点一次即取消该标签 |
| **任一 / 全部** | 分段控件切换匹配语义：`任一` = 带其中任意一个标签；`全部` = 必须同时带全部标签 |
| **清除筛选** | 工具条右侧一个按钮；空状态里也放了一个，恢复完整列表 |
| **空状态提示** | 没有匹配时显示「没有符合标签的插件」+ 当前已选标签 + 一键清除 |
| **「未标注」伪标签** | 没有任何标签的插件（例如手工放进插件目录的）会归到「未标注」，不会永远筛不出来 |
| **死路标签弱化** | 加上去也匹配不到任何插件的标签会被弱化并划线，鼠标悬停给出原因（仍可点击） |
| **标签数量** | 每个标签后面显示当前视图里的插件数（可在设置里关掉） |
| **记住筛选状态** | 已选标签与匹配方式写进插件存储，重启主程序后恢复（可在设置里关掉） |
| **能力标签（可选）** | 默认关闭；打开后额外聚合 `manifest.capabilities` 生成的能力标签（如「网络」「本地文件」），用虚线边框区分 |
| **标签总览页** | 侧边栏「插件 → 标签筛选」：不与面板同屏时也能看全部标签并预选，附「复制诊断」 |
| **开箱即用的降级** | 宿主一个标签都没给出来时，明确提示原因，而不是只留一个孤零零的「未标注」 |

侧边栏入口、筛选条开关、匹配方式、是否显示数量都能在**插件设置**里改，改完立即生效（不用重启）。

## 三、设计决策（以及为什么不那样做）

### 3.1 为什么读 DOM 而不是调宿主 API

宿主并没有「按标签查询插件列表」的接口，而**卡片上的标签本来就是宿主渲染出来的**：
索引 `echo-plugins.json` 里的 `tags` 会被宿主持久化到 `app_kv` 的 `plugins:catalog-tags:<id>`，
再渲染成卡片里的标签元素。直接读它有三点好处：

1. 与宿主看到的一致（不需要自己再解析一次索引、也不会因为索引格式变化而失效）；
2. 「已安装」「在线插件」两个视图结构一致，一套代码全覆盖；
3. 不需要申请任何 capability，宿主收紧权限也不会影响它。

### 3.2 为什么用「行内 style」隐藏卡片，而不是加 class

宿主卡片的 class 是动态绑定 `:class="['plugin-card', { 'is-disabled': ... }]"`。
用户在插件管理页里启用/停用一个插件时，这个绑定的字符串会变，**Vue 会整串重写 `el.className`**，
把我们加的 class 一起抹掉 —— 表现为「点了禁用之后筛选就漏出一张卡片」。
改成写行内 `element.style.display` 就安全了：卡片的根元素没有 style 绑定，Vue 从不触碰它。

### 3.3 为什么不直接用 `ctx.dom.observe`

它的语义是「**每个新出现的匹配元素只回调一次**」（按元素去重）。
宿主机内原地重渲染（换一批、状态变化）时元素还是原来那个，不会再触发，
拿它做「实时过滤」会漏更新。所以这里自己起一个 `MutationObserver`
（只监听 `childList` 与 `aria-busy`）+ 1s 兜底轮询收敛，并且**每次同步只写有变化的节点**。

### 3.4 计数与排序：稳定优先

- chip 上显示的是**当前视图里带该标签的插件数**，与选择无关 —— 所以点标签时数字不会跳；
- chip 的排序也只看这个计数与标签名，**不掺「选中后会匹配多少」** —— 否则点一下整排顺序就变，
  下一次点击很可能打在你没想点的标签上；
- 「选中后会匹配多少」只出现在鼠标悬停提示里，以及用来决定某个标签要不要弱化（划掉）。

### 3.5 会读到的宿主 DOM（已按 app.asar 逐字节核验，v2.3.2-beta.6）

| 选择器 | 用途 |
| --- | --- |
| `.plugin-card-grid` | 卡片网格；**骨架屏那一版带 `aria-busy="true"`，必须跳过** |
| `.plugin-card` | 单张插件卡片 |
| `.marketplace-tags > span` | 目录标签（本插件的主要数据源） |
| `.plugin-feature-tags > span` | 能力标签（可选取数） |
| `.plugin-card-id` | 卡片上的 `ID: <pluginId>` |
| `.plugin-card-name` | 卡片上的 `<h3>` 插件名 |
| `.plugin-content` | 筛选条的注入容器（挂在网格正上方） |

## 四、坑点（踩过的）

1. **骨架屏卡片和真卡片长一样**：加载中宿主会渲染 6 张骨架卡，它们同样带
   `.plugin-card` / `.marketplace-tags`。只能靠**网格的 `aria-busy="true"`** 区分，
   否则加载期间会把占位标签也聚合进 chip 列表。
2. **标签要去重**：同一张卡片上可能出现同一个标签的两种写法（`Lyrics` / `lyrics`），
   卡片读取阶段与快照重建阶段都必须按小写 key 去重，否则 chip 计数会翻倍。
3. **插件管理页可能被挂载两处**（主路由 + 标题栏「更多」里也有入口）：
   同一个插件会出现两张卡片，所以实体按 id 合并、把所有 DOM 元素收集到 `elements` 数组，
   过滤时一起处理 —— 否则计数翻倍、还会漏掉其中一处。
4. **停用/关闭时必须还原卡片**：`display:none` 是写进 DOM 的，
   插件停用或把筛选条关掉时不还原，用户的插件列表就会一直少几张，看起来像插件丢了。
5. **渲染函数里读的必须是响应式数据**：插件内部的选择集合与匹配模式是普通变量，
   界面统一经 `view.selected` / `view.mode` 读，否则「点了没反应」。
6. **`aria-busy` 之外不要监听 `class`**：自己写 style 不会触发观察回调，
   但监听 class 会与宿主的重渲染互相触发，得不偿失。

## 五、设置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 在插件面板显示标签筛选条 | 开 | 关掉后不再过滤，卡片立即恢复完整列表 |
| 侧边栏显示「标签筛选」入口 | 开 | 关掉只保留面板内的筛选条 |
| 记住筛选状态 | 开 | 选中标签与匹配方式持久化，重启后恢复 |
| 在标签上显示插件数量 | 开 | 关掉后 chip 只显示标签名 |
| 同时纳入「能力标签」 | 关 | 打开后把 `capabilities` 生成的能力标签也纳入 |
| 调试日志 | 关 | 在开发者控制台输出详细日志 |
| 默认匹配方式 | 任一 | 未选择时的初始匹配语义（改完立即生效） |

```powershell
# 无头集成测试：真实 Vue 3 ESM + 仿真宿主 DOM + mock ctx
# 覆盖标签提取、单选/多选、任一/全部、空状态、未标注、骨架屏跳过、
#      大小写归一、宿主重渲染、视图切换、设置面板、命令、独立页面、停用还原、重启恢复、无标签降级
node tests/tag-filter.smoke.mjs        # 203 项

# 变异测试：把关键行为逐个改回 bug 版本，确认断言真的会失败
node tests/tag-filter.mutate.mjs       # 16 个变异
```

`tests/tag-filter.mutate.mjs` 里每个变异对应一条真实风险，例如「用 class 而不是行内 style
隐藏卡片」「标签不去重」「快照派生失效」。**只有确认「改坏了会红」，才敢相信「绿」。**

## 七、安全边界

- 只读宿主页面的 DOM（插件卡片、网格、标签），不修改宿主任何数据；
- 只在**自己的命名空间**下读写 `ctx.storage`（`plugin:tag-filter:*`）；
- 不发起任何网络请求，不申请任何 capability；
- 不采集、不上传任何用户数据。
