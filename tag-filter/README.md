# 插件标签筛选（`tag-filter`）

> 当前版本 **1.1.0**（新增：条件分组、安装/启用状态筛选、分组折叠与一键收起、自定义标签组）

给 EchoMusic 的「设置 → 插件」面板加一条**分组式筛选条**：把面板里所有插件的**标签**与**状态**
自动聚合成条件供点选，实时过滤卡片列表，没有匹配时给出友好的空状态。

装上、启用，回到插件管理页就能看到。不用配任何东西。

## 一、它长什么样

```
设置 → 插件
┌──────────────────────────────────────────────────────────────────────────────┐
│  [ 搜索框 ]      [ 来源 ▾ ]                              [ 刷新 ]            │  ← 宿主原有工具条
│  已安装插件                                       共 22 个 · 18/22 个已启用
│                                                                              │
│  筛选插件    [收起]  [任一|全部]  [清除筛选]                                   │  ← 本插件注入
│  共 22 个插件 · 18 个标签 · 2 个未标注
│  ▾ 安装状态    2 项
│      (已安装 18) (未安装 3) (可更新 1)
│  ▾ 启用状态    已选 1 / 2
│      (已启用 16) (未启用 6)
│  ▾ 目录标签    已选 1 / 18
│      (lyrics 5) (floating-window 4) (appearance 3) … (未标注 2)
│                                                                              │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐                                │
│  │ plugin-card│ │ plugin-card│ │ plugin-card│   ← 不匹配的卡片被隐藏          │
│  └────────────┘ └────────────┘ └────────────┘                                │

收起之后长这样（标签多、嫌占地方时用）：

```
筛选插件  (lyrics ×) (未启用 ×)  [展开筛选（4 组）] [任一|全部] [清除筛选]
显示 3 / 22 · 已选 2 个条件 · 隐藏 19 个
```

## 二、功能

### 1. 条件分组

条件按维度分组，每组一个可点折叠的标题，并显示「已选 / 总数」：

| 分组 | 内容 | 什么时候出现 |
| --- | --- | --- |
| **快捷组** | 你自定义的标签组（见下） | 建过组之后 |
| **安装状态** | 已安装 / 未安装 / 可更新 | 在线插件视图（只有在线卡暴露安装状态） |
| **启用状态** | 已启用 / 未启用 | 已安装视图里有停用/无效的卡片时 |
| **目录标签** | `echo-plugins.json` 里的 tags（含「未标注」） | 总有 |
| **能力标签** | 由 `manifest.capabilities` 生成（如「网络」「本地文件」） | 设置里打开该开关后 |

> **只在某个维度真的有两种以上取值时才显示这一组**。所以「已安装视图」里不会冒出
> 「安装状态：已安装 22」这种筛不出任何东西的噪音组。

### 2. 安装状态 / 启用状态筛选

- **安装状态**（在线插件视图）：`已安装` / `未安装` / `可更新`；
- **启用状态**（已安装视图）：`已启用` / `未启用`（含停用、无效、与主程序不兼容 —— 即宿主认为「没在跑」的）。

维度之间是 **AND**（标签 AND 状态），维度内部是 **OR**（已安装 OR 未安装）。
它们与标签一样带实时计数，且计的是**稳定值**（不随你选了什么而跳动）。

### 3. 分组折叠 + 一键收起/展开

- 点分组标题 → 折叠/展开该组（状态会记住）；
- 点「收起」→ 整个条件区收成一行，只留**已选条件**（点一下即可取消该条件）；
- 折叠状态与会选择一起持久化，重启主程序后保持；
- 命令 `toggle-tag-filter-expand` 也能切。

### 4. 自定义标签组

把常用的几个标签打包成一个组，点一下就能同时选中它们 —— 相当于**筛选预设**：

- 做法：在筛选条里选好标签 → 到「标签筛选」页面点「新建」；
- 组 chip 显示 `已选/成员数`，三态：未选 / 部分选中（虚线）/ 全选；
- 点击语义：未全选 → 补全为全选；已全选 → 全部取消（组外标签不受影响）；
- 管理：改名、用当前筛选覆盖成员、单个成员点 × 移除、删组；成员被删空时整组自动清理。

### 5. 其它（1.0.0 就有）

| 功能 | 说明 |
| --- | --- |
| **自动聚合标签** | 读取卡片上的标签，去重（大小写不敏感）、按出现次数排序 |
| **多选实时过滤** | 点 chip 立即过滤；「任一 / 全部」切换标签维度的匹配语义 |
| **清除筛选** | 工具条一个按钮；空状态里也有一个 |
| **空状态提示** | 「没有符合条件的插件」+ 当前已选条件 + 一键清除 |
| **「未标注」伪标签** | 没有任何标签的插件归入此组，不会永远筛不出来 |
| **死路标签弱化** | 加上去也匹配不到的标签被划线，悬停给出原因（仍可点） |
| **记住筛选状态** | 选中条件、折叠状态、自定义组都会持久化 |
| **标签总览页** | 侧边栏「插件 → 标签筛选」：不与面板同屏时也能看全部条件并预选，含自定义组管理与「复制诊断」 |
| **降级提示** | 宿主一个标签都没给出来时明确说明原因 |

## 三、设计决策（以及为什么不那样做）

### 3.1 为什么读 DOM 而不是调宿主 API

宿主并没有「按标签/状态查询插件列表」的接口，而**标签与状态本来就是宿主渲染在卡片上的**：
索引 `echo-plugins.json` 的 `tags` 被宿主持久化到 `app_kv` 的 `plugins:catalog-tags:<id>`，
再渲染成 `.marketplace-tags` 里的标签；状态则来自卡片自身的类名与徽章文案。直接读它：

1. 与宿主看到的一致（不用自己再解析一次索引，也不会因为索引格式变化而失效）；
2. 「已安装」「在线插件」两个视图结构一致，一套代码全覆盖；
3. 不需要申请任何 capability，宿主收紧权限也不影响。

### 3.2 状态是怎么判出来的（不猜、不新增数据）

| 状态 | 依据 |
| --- | --- |
| 视图种类 | 卡片根节点类名：在线卡多一个 `marketplace-card` |
| 已安装 / 未安装 / 可更新 | 在线卡 `.plugin-status-badge` 的文案（`已安装` / `未安装` / `可更新`），安装按钮文案兜底 |
| 已启用 / 未启用 | 已安装卡是否带 `is-disabled`（宿主定义：`!enabled \|\| invalid \|\| !compatible`，即「没在跑」） |

> ⚠️ **两个视图的 `is-disabled` 含义不同**：在线卡上它表示「与主程序不兼容」。
> 所以在线卡的启用状态一律记为「未知」，绝不跨视图套用同一套判定 ——
> 并且「宁严勿松」：用户筛「未安装」时，状态不明的卡片会被排除，而不是混进来。

### 3.3 为什么用「行内 style」隐藏卡片，而不是加 class

宿主卡片的 class 是动态绑定 `:class="['plugin-card', { 'is-disabled': ... }]"`。
用户在插件管理页里启用/停用一个插件时，这个绑定的字符串会变，**Vue 会整串重写 `el.className`**，
把我们加的 class 一起抹掉 —— 表现为「点了禁用之后筛选就漏出一张卡片」。
改成写行内 `element.style.display` 就安全了：卡片的根元素没有 style 绑定，Vue 从不触碰它。

### 3.4 为什么不直接用 `ctx.dom.observe`

它的语义是「**每个新出现的匹配元素只回调一次**」（按元素去重）。
宿主机内原地重渲染（换一批、状态变化）时元素还是原来那个，不会再触发，
拿它做「实时过滤」会漏更新。所以这里自己起一个 `MutationObserver`
（只监听 `childList` 与 `aria-busy`）+ 1s 兜底轮询收敛，并且**每次同步只写有变化的节点**。

### 3.5 计数与排序：稳定优先

- chip 上显示的是**当前视图里的插件数**，与选择无关 —— 点条件时数字不会跳；
- chip 的排序也只看这个计数与名称，**不掺「选中后会匹配多少」** —— 否则点一下整排顺序就变，
  下一次点击很可能打在你没想点的条件上；
- 「选中后会匹配多少」只出现在悬停提示里，以及用来判断某个条件要不要弱化（划线）。

### 3.6 会读到的宿主 DOM（已按 app.asar 逐字节核验，v2.3.2-beta.6）

| 选择器 | 用途 |
| --- | --- |
| `.plugin-card-grid` | 卡片网格；**骨架屏那一版带 `aria-busy="true"`，必须跳过** |
| `.plugin-card` | 卡片根节点；带 `marketplace-card` 的是在线视图的卡片 |
| `.marketplace-tags > span` | 目录标签（主要数据源） |
| `.plugin-feature-tags > span` | 能力标签（可选取数） |
| `.plugin-status-badge` | 状态徽章（在线卡 → 安装状态） |
| `.marketplace-install-btn` | 安装按钮（兜底判据） |
| `.plugin-card-id` / `.plugin-card-name` | `ID: <pluginId>` / `<h3>` 插件名 |
| `.plugin-content` | 筛选条的注入容器（挂在网格正上方） |

## 四、坑点（踩过的）

1. **骨架屏卡片和真卡片长一样**：加载中宿主会渲染骨架卡，它们同样带
   `.plugin-card` / `.marketplace-tags`。只能靠**网格的 `aria-busy="true"`** 区分。
2. **维度值不要用布尔表示**：`enabled` 一开始写成 `true/false`，而维度定义里是 `'on'/'off'`，
   两边对不上 → 该维度一个 chip 都生不出来、整组静默消失。**表示形式必须统一成字符串 id**
   （1.1.0 用测试把这条钉住了）。
3. **标签要去重**：同一张卡片上可能出现同一个标签的两种写法（`Lyrics` / `lyrics`），
   卡片读取阶段、快照重建阶段、以及**自定义组的成员列表**都必须去重，否则计数会翻倍、
   「全选」判定永远不成立。
4. **插件管理页可能被挂载两处**（主路由 + 标题栏「更多」里也有入口）：
   同一个插件会出现两张卡片，所以实体按 id 合并、把所有 DOM 元素收集到 `elements` 数组，
   过滤时一起处理 —— 否则计数翻倍、还会漏掉其中一处。
5. **停用/关闭时必须还原卡片**：`display:none` 是写进 DOM 的，
   插件停用或把筛选条关掉时不还原，用户的插件列表就会一直少几张，看起来像插件丢了。
6. **渲染函数里读的必须是响应式数据**：插件内部的选择集合与匹配模式是普通变量，
   界面统一经 `view.*` 读，否则「点了没反应」。
7. **`aria-busy` 之外不要监听 `class`**：自己写 style 不会触发观察回调，
   但监听 class 会与宿主的重渲染互相触发，得不偿失。

## 五、设置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 在插件面板显示筛选条 | 开 | 关掉后不再过滤，卡片立即恢复完整列表 |
| 侧边栏显示「标签筛选」入口 | 开 | 关掉只保留面板内的筛选条 |
| 记住筛选状态 | 开 | 选中条件、分组折叠状态、自定义组都持久化，重启后恢复 |
| 在标签上显示插件数量 | 开 | 快捷组另外显示「已选/成员数」 |
| 显示「安装状态 / 启用状态」 | 开 | 关掉后只按标签筛选 |
| 同时纳入「能力标签」 | 关 | 打开后把 `capabilities` 生成的能力标签单独归到一组 |
| 调试日志 | 关 | 在开发者控制台输出详细日志 |
| 默认匹配方式 | 任一 | 标签维度的初始匹配语义 |

node tests/tag-filter.mutate.mjs       # 26 个变异
```

`tests/tag-filter.mutate.mjs` 里每个变异对应一条真实风险，例如「用 class 而不是行内 style
隐藏卡片」「维度值用布尔表示导致整组消失」「两个状态维度变成 OR」「单一取值的维度也成组」
「点快捷组不是全选/全取消」。**只有确认「改坏了会红」，才敢相信「绿」。**

## 八、安全边界

- 只读宿主页面的 DOM（插件卡片、网格、标签、状态徽章），不修改宿主任何数据；
- 只在**自己的命名空间**下读写 `ctx.storage`（`plugin:tag-filter:*`）；
- 不发起任何网络请求，不申请任何 capability；
- 不采集、不上传任何用户数据。
