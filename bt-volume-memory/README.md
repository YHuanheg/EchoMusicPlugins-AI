# 音量记忆（bt-volume-memory）

> 当前版本 **1.0.0** · 需要 EchoMusic **≥ 2.3.2-beta.6**（原生 helper 走 `ctx.process.launch`）

按**音频输出设备**记住音量，设备重连时自动恢复，并弹出一个音量浮层。

默认只处理**蓝牙设备**。解决的问题是：蓝牙耳机断电时，Windows 会把这个音频端点整条销毁，
重连时重建 —— 你设好的音量随之丢失，通常回到蓝牙栈决定的默认值（往往大得吓人，一戴上就炸耳朵）。
这个插件在应用层替你记账：给每个设备记一条「音量百分比」，重连时写回去。

参考实现是 [EarTrumpet](https://github.com/File-New-Project/EarTrumpet)（MIT）的「记住蓝牙设备音量」，
本插件复刻它的行为契约。**不依赖 EarTrumpet**：不需要装它，也不会调用它。

---

## 安装

把 `bt-volume-memory` 目录放进 EchoMusic 的插件目录，然后在「插件管理」里启用：

```
%APPDATA%\echo-music\plugins\bt-volume-memory\
```

需要 EchoMusic **≥ 2.3.2-beta.6**。

### 首次启动会弹一次授权

插件目录里带了一个原生程序 `Host/VolumeHelper.exe`，用来读写 Windows 的音频端点
（EchoMusic 插件跑在渲染进程里，纯 JS 碰不到系统音量）。

宿主在启动插件目录内的程序前会弹窗询问一次：

> **允许插件启动本地程序？** — 插件: 音量记忆 (bt-volume-memory) — 程序: Host/VolumeHelper.exe

点「允许并记住」即可。这个确认**每个插件版本、每个 exe 哈希只会问一次**；
插件升级或 helper 重新编译后会再问一次（这是宿主的机制，不是插件的选择）。

点了「取消」的话功能不可用，设置页会给出「重新授权并启动」按钮。

## 使用

启用后基本不需要操作：

1. 把耳机连上，用系统音量键或音量条把它调到你想要的音量 → 插件记录下来；
2. 耳机断电、再开机重连 → 音量自动回到你上次设的值，屏幕下方浮出一个音量提示。

设置页「音量记忆」里有：

| 项目 | 说明 |
| --- | --- |
| **记住设备音量** | 总开关。关掉后**既不记忆也不恢复**（已有记录不会被覆盖，重新打开即恢复生效） |
| **作用范围** | 「仅蓝牙设备」（默认）或「所有输出设备」 |
| **设备记录** | 所有记录过的设备，**含当前未连接的**：设备名、记忆音量、当前音量、连接/未连接、设备类型（蓝牙·立体声 / 免手持 / LE Audio / USB / 板载）、上次见到的时间 |
| **忘记** | 只删这一条记录，设备本身不动。下次你再调音量会被重新学到 |
| **清空全部记录** | 删掉所有记录（设备不受影响） |
| **刷新设备列表 / 重启本地服务 / 预览音量浮层** | 排查与预览用 |

## 行为细节（都与 EarTrumpet 对齐）

- **音量 0 永不记忆**：很多蓝牙栈在断开过程中会把端点打到 0，记住它等于还你一副静音耳机。
- **只有「重连」才弹浮层**：首次连接（还没有记录）、以及程序启动时就已经连着的设备都不弹 ——
  否则每次开程序都弹一层，那是噪音。
- **恢复后以实际生效值为准**：有些端点会 snap 到自己支持的档位而不是你请求的值，
  这时记下的是实际值，避免每次重连都再 snap 一次。
- **拖动音量条只写一次**：连续变化合并成一次落盘（2 秒防抖）。
- 蓝牙耳机常同时存在「立体声」与「免手持」两个端点，重连时它们几乎同时恢复，
  浮层**原地刷新**而不是叠两层。

## 边界与隐私

- helper **只监听 `127.0.0.1`**，需要令牌才能调用；不监听外网，**不联网**。
- **不写注册表、不装服务、不开机自启。** 只在 EchoMusic 运行期间活着：
  EchoMusic 退出或插件被禁用时 helper 会被关掉，helper 自己也有空闲自退兜底。
- helper 读写的是**音频端点音量**（等同于系统音量条的位置），不碰音频流、不录音、不采集任何内容。
- 记忆表存在 EchoMusic 的插件私有存储里，不上传任何地方。
- 只在 **Windows** 上工作；其它平台插件会提示本地服务不可用，不会有副作用。

## 排查

| 现象 | 处理 |
| --- | --- |
| 设置页显示「异常：你取消了允许插件启动本地程序」 | 点「重新授权并启动」 |
| 显示「插件安全模式已开启」 | EchoMusic 处于插件安全模式，先退出安全模式 |
| 显示「helper 起来了但读不到音频端点」 | 系统音频服务（Audiosrv）异常，或音频端点驱动有问题 |
| 显示「helper 已停止响应」 | 点「重启本地服务」；反复出现请带上设置页里的端口与 pid 反馈 |
| 换了耳机但列表里没出现 | 该设备不是蓝牙设备（默认范围只看蓝牙），把「作用范围」改成「所有输出设备」 |
| 音量没被恢复 | 确认总开关是开的；确认这条记录存在（可能之前点了「忘记」）；确认该设备属于当前作用范围 |

`Host/VolumeHelper.exe --help` 可以手工查看它的参数；加 `--debug` 会额外注册一个
`POST /debug/reconnect`（把指定端点当成「刚重连」跑一遍恢复流程），用于验证恢复链路。

## 重新构建 helper

插件目录里带了源码，不需要联网：

```powershell
powershell -ExecutionPolicy Bypass -File Host\build.ps1
```

需要 .NET SDK（或 MSBuild + .NET Framework 4.6.2 目标包）。产物是 `Host/VolumeHelper.exe`，
约 38 KB，运行只需要 Windows 自带的 .NET Framework 4.8 —— **用户端零额外依赖**。
