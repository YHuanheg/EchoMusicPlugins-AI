# GitHub 加速器 · EchoMusic 插件

为 **EchoMusic** 的更新检查与在线插件市场下载挑选最快的 GitHub 加速线路，并提供多平台链接转换。

- **插件 id**：`gh-accelerator`
- **最低主程序版本**：EchoMusic `>= 2.3.0`
- **能力声明**：`unrestrictedNetwork`（线路测速需要主进程 Axios，绕开渲染进程 CORS）、`webServer`（Xget 本地桥）

## 这个插件解决什么问题

EchoMusic 在「设置 → 更新 → **GitHub 加速地址**」里可以填一个加速前缀，用于：

1. 应用自身的版本更新检查与安装包下载；
2. 在线插件市场的插件源索引、`manifest.json` 与插件 zip 下载。

默认它是空的，也就是直接访问 GitHub。国内网络下这一步经常很慢甚至失败。本插件做三件事：

1. **实测而不是猜**：对每条线路发起一次真实 GitHub 文件下载，同时得到可达性、耗时与吞吐，然后排序；
2. **一键落地**：把最快的一条写进宿主的「GitHub 加速地址」，并立刻回读校验；
3. **补上 Xget**：提供 Xget 形态的链接转换（支持 GitLab / Hugging Face / npm / PyPI 等 20+ 平台）。

## ⚠️ 关键限制（实测确认）

EchoMusic 内部把该设置拼成：

```
<你填的前缀> + "/" + <完整原始 URL>
```

例如填 `https://gh-proxy.com`，请求 `https://github.com/a/b/archive/main.zip` 时实际访问
`https://gh-proxy.com/https://github.com/a/b/archive/main.zip`。

**这是 gh-proxy 的形态。Xget 是「路径重写」形态**（`https://host/gh/owner/repo/path`），把 Xget 域名填进去会拼成 404。实测：

| 请求 | 结果 |
| --- | --- |
| `https://xget-ckf.pages.dev/gh/hoowhoami/EchoMusic/raw/main/docs/plugin-system.md` | ✅ 200 |
| `https://xget-ckf.pages.dev/https://raw.githubusercontent.com/hoowhoami/EchoMusic/…` | ❌ 404 |
| `https://gh-proxy.com/https://raw.githubusercontent.com/hoowhoami/EchoMusic/…` | ✅ 200 |

所以插件把线路分成两类：

- **gh-proxy 形态**：可以「写入宿主设置」，列表里带 `gh-proxy 形态` 标签；
- **Xget 形态**：全平台、速度通常更好，**通过本地桥接管加速**（见下一节），列表里带绿色 `可经本地桥加速` 标签。

## Xget 加速是怎么做到的（本地桥）

插件用 `ctx.webServer` 在 `127.0.0.1` 上起一个**只做 302 跳转**的本地桥，然后把宿主的「GitHub 加速地址」
指向它（`http://127.0.0.1:47823`）：

```
宿主请求  http://127.0.0.1:47823/https://github.com/o/r/archive/refs/heads/main.zip
   ↓ 本地桥 302（纯路径换算，不占带宽）
Xget      https://xget-ckf.pages.dev/gh/o/r/archive/refs/heads/main.zip
   ↓ 200
         （真正的文件内容，由 Xget 的边缘网络提供）
```

于是**自建 Xget 也能直接给宿主加速，不需要额外部署任何东西**。

为什么是重定向而不是反向代理：宿主给本地服务的单次响应体上限是 **8 MB**，而插件 zip 允许到 **80 MB**，
代理必然失败；重定向还能保留 Xget 自己的 Range / 缓存 / 重试语义，且不占用本地带宽。
宿主下载走 `session.fetch()`，默认跟随 3xx，所以 302 会被正常解析。

### 端到端实测（本地桥 + 自建 Xget）

| 通过桥请求 | 结果 | 传输量 | 吞吐 |
| --- | --- | --- | --- |
| `EchoMusicPlugins` 仓库 zip（插件市场真实场景） | ✅ 200 | 465 KB | 308 KB/s |
| `codeload` 大包（等价换算） | ✅ 200 | 23.9 MB | **4.5 MB/s** |
| `raw` 小文件（探测文件） | ✅ 200 | 3.8 KB | — |
| 含 query 的 URL | ✅ 200 | 16.8 KB | — |
| 不支持的主机 | ✅ 502（按设计拒绝） | — | — |

### 使用

1. 打开「加速器」页面 →「Xget 本地加速」卡片；
2. 选好桥接线路（默认自动用测速最快的 Xget）与端口；
3. 点「**启用 Xget 加速**」→ 插件启动本地桥并写入宿主设置（会回读校验）；
4. 点「**自检**」可验证完整链路（本地桥 → 302 → Xget → 真实文件字节）；
5. 不再需要时点「停用 Xget 加速」，会清空宿主设置并关闭端口。

### 需要注意

- 本地桥**随插件生命周期运行**：插件被禁用/卸载、或 EchoMusic 退出时端口自动释放。
  此时宿主会按官方逻辑自动回退到原始 GitHub（不会卡住更新），但等于失去加速。
- 插件启用状态下重启主程序，只要「启动时自动恢复本地桥」是开的，桥会自动重新监听（端口固定，所以不会失效）。
- 想要**插件关掉也生效**，请改用云端桥：仓库 `docs/xget-bridge/`——在你的 Xget Pages 项目加一个
  catch-all Function，一次部署长期有效。

## 功能一览

- **一键测速**：并发实测全部内置 + 自定义线路，按吞吐排序，绿色可用 / 红色失败；
- **在线插件界面状态条**：在「插件管理 → 在线插件」的工具条下方直接显示加速情况（见下节）；
- **刷新拉取进度**：刷新在线插件时显示阶段、百分比、已拉取数量、速率与预计剩余；可选用「接管刷新按钮」拿到精确进度（见下节）；
- **Xget 加速（本地桥）**：一键把自建 Xget 接入宿主加速地址，含完整链路自检；
- **「进入本页自动测速」开关**：真实开关控件 + 「已开启 / 已关闭」状态标签，与设置面板里的同一项联动（5 分钟内已测过则跳过）；
- **侧边栏入口自检**：检测「插件」分组是否被折叠（折叠会让入口整组消失）并一键展开；入口开关即时生效；
- **应用最快线路**：写入宿主 `githubProxyUrl`，回读校验，失败时给出可复制的手动值；
- **吞吐测速**：针对单条线路下载一个较大文件，区分「能连通」和「真的快」；
- **线路管理**：预置 24 条实测可用的 gh-proxy 公益节点（带地区标签）+ 2 条 Xget，支持自定义增删；
- **负载均衡**：可选「在最快的 4 条里随机」，避免把公益节点打挂；
- **链接转换 / 批量转换**：单条或整行批量转换，一键复制，可批量复制全部结果；
- **排除规则**：正则或字面量，命中即跳过；
- **统计**：转换次数、成功 / 失败、写入宿主次数、最近测速时间；
- **设置面板**：并发数、超时、测速文件、体积上限、本地桥端口与自动恢复、排除规则、调试日志。

### 负载均衡（默认关闭）

公益节点带宽有限，如果所有人都固定打同一条，它会更快失效 —— XIU2 的脚本特意做了
「美国节点每次随机，分散压力」的设计。插件提供了对应选项：

- 关闭（默认）：`应用最快线路` 就用实测最快的那一条；
- 开启：改为在**实测最快的 4 条里随机**挑一条，用少量速度换取节点存活率，按钮文案也会同步变化。

### 关于 jsDelivr

XIU2 的清单里还推荐了 `jsdelivr`（`/gh/user/repo@branch/file`）。本插件**没有**收进来，因为它的限制
与「插件市场下载」这个场景冲突：**不支持超过 50 MB 的文件**（插件包上限 80 MB），
且**不支持形如 `v1.2.3` 的分支/标签名**。它更适合单文件 Raw 场景。



## 在线插件界面里的加速状态条

在「插件管理 → 在线插件」页，插件的工具条（搜索框那一行）下方会多出一条状态条，
不用回加速器页面就能看清当前到底有没有在加速：

| 状态 | 表现 |
| --- | --- |
| 未启用 | 灰色 ·「未启用加速 · 直连 GitHub」+ 提示实际影响 |
| 已启用 | 主题色描边 ·「加速已启用」+ 当前线路名与地址（走本地桥时会写明 `本地桥 http://127.0.0.1:47823 → https://xget-ckf.pages.dev`）+ 已测得的吞吐 |
| 异常 | 橙色警告 ·「加速地址指向本地桥，但本地桥未运行」+ 处理建议 |

状态条右侧带三个快捷操作：**测速**、**启用 Xget 加速**（已启用时自动隐藏）、**打开加速器**。

实现上走 `ctx.dom.observe('.marketplace-toolbar', ...)` + `ctx.ui.mount(容器, 组件)`：
只在「在线插件」标签页注入，宿主重渲染后会自动重挂，并且有防重复注入与失效节点回收。
可在设置面板用「在线插件界面显示加速状态条」开关关闭。

## 刷新在线插件时的「拉取进度 / 数量 / 速率」

点「刷新」以后，状态条下方会多出一条进度条，显示当前阶段、百分比、已拉取数量、拉取速率、已用时间与预计剩余。

宿主的刷新链路（逆向 `app.asar` 得到，无官方文档）：

```
刷新按钮 → loadMarketplace(refresh=true) → N_() → D_()
  → 每个启用的源 并行执行：
      ① x_(indexUrl)   拉 echo-plugins.json（这里才知道插件总数 N）
      ② b_()           并行拉 N 个 manifest（Promise.allSettled）
      ③ C_()           返回 pluginCount
  → Pg(cache) 写缓存 → fetchedAt = Date.now()
  → E_() 补 iconUrl/downloadUrl + POST 热度统计
```

**关键前提**：宿主**没有**向插件暴露任何进度事件，也没有字节回调。
所以进度是「推定」出来的，插件用了三路融合：

| 路数 | 手段 | 能拿到什么 |
| --- | --- | --- |
| ① DOM 骨架 | `.plugin-card-grid[aria-busy="true"]` 存在 ⇒ 仍在加载（宿主渲染 6 张骨架卡） | 是否还在拉、处于哪一段 |
| ② 卡片计数 | 网格去掉 `aria-busy` 后的真实 `.plugin-card` 数量 | 「已到手」的可见代理 |
| ③ 主动探针 | 自己按宿主同样的加速前缀拉一次索引 JSON | **插件总数 N**（进度分母）与真实字节/耗时（速率） |

三路互相校验：分母可信就用「已到手 / 总数」，否则退回阶段权重渐近推进。
骨架卡和真实卡片都带 `.plugin-card.marketplace-card`，所以必须靠**网格的 `aria-busy`** 区分，不能看卡片自身。

为避免「刷新太快、250ms 轮询一次都没撞上」导致整轮进度不显示，
插件还会在宿主刷新按钮上挂一个**捕获阶段、不拦截**的点击监听 —— 点下去立刻开表，
宿主自己的刷新行为完全不受影响。

「已用 / 约剩 / 完成后 12 秒倒计时」这类时间文案靠一个 500ms 心跳驱动刷新，
否则它们会冻在第一次的值上（时间不是响应式依赖）。

索引地址与宿主**实际取数**用的构造器完全一致（asar 里是 `F_(repo, 'echo-plugins.json')`）：

```
{githubProxyUrl}/{https://raw.githubusercontent.com/hoowhoami/EchoMusicPlugins/HEAD/echo-plugins.json}
```

复用宿主自己的前缀，测出来的速率才贴近真实体验。

> 注意别被宿主的 `indexUrl` 字段误导：来源对象上那个 `indexUrl`（`L_(repo, ...)`）是
> `https://github.com/<owner>/<repo>/blob/HEAD/<file>` 的**展示用**形态，直接用它会拿到 HTML；
> 真正取数走的是 `F_(repo, path, ref)` 的 **raw** 形态，也就是上面这一条。

### 探针的「加速失败 → 回落直连」

宿主对索引请求用的是双段策略（asar 里的 `Nu({acceleratorEnabled, accelerated, github, onAcceleratorFailure})`）：
先打加速地址，**失败再回落直连原始 GitHub**。探针照做：

1. 先探 `{加速前缀}/{raw URL}`；
2. 失败、或返回的不是带 `plugins` 数组的合法 JSON（例如镜像返回了 HTML 错误页），
   再探 `{raw URL}` 直连；
3. 直连成功时，进度条会标 **「总数经直连取得」**，让用户知道总数不是走加速拿到的。

只探加速那一次的话，镜像偶发抖动就会让「插件总数」整个丢掉、进度退回阶段估算 ——
而总数正是这个功能要给用户看的东西。探针默认超时也据此从 4 s 放宽到 **8 s**
（宿主自己给索引请求的预算宽得多，过早放弃等于白白丢掉分母）。

### 精确模式：接管「刷新」按钮（默认关闭）

推定总有误差。打开设置里的**「接管「刷新」按钮（精确进度）」**后，插件会在宿主刷新按钮上层盖一个
透明命中层，点下去改由插件自己驱动一遍拉取：

- 先探针拿总数（走 `probeMarketplaceIndex`）
- 再调宿主自己的 IPC `window.electron.plugins.marketplace.list({ refresh: true })`
  —— 拿回的是宿主**已解析好**的 manifest 数组，长度即真实支数
- 分阶段串行推进，百分比与数量都是真值，进度条上标「精确模式」

为什么要盖命中层而不是 `.click()` 代理：宿主在拉取中会给按钮加 `disabled`，直接点会被吞掉。
盖层方式完全不动宿主 DOM，关掉开关时整块移除，**零残留**。

### 相关设置

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 显示刷新进度条 | 开 | 总开关，关掉后不显示进度条也不做 DOM 观测 |
| 刷新时探测插件总数 | 开 | 关掉后只能按阶段权重估算百分比（仍可用，只是精度低） |
| 探针超时 | 8000 ms | 可调 1000–15000 ms；放宽是为了别过早丢掉「插件总数」 |
| 接管「刷新」按钮 | 关 | 打开后进度变为真实值，代价是替换宿主的刷新行为 |

## 安装

### 方式一：本地安装（最快）

把 `gh-accelerator/` 整个文件夹复制到 EchoMusic 插件目录：

```
%APPDATA%\echo-music\plugins\gh-accelerator\
```

（macOS：`~/Library/Application Support/echo-music/plugins/`；Linux：`~/.config/echo-music/plugins/`）

然后在 EchoMusic「插件管理」里刷新插件列表并启用。侧边栏「插件」分组会出现「加速器」入口。

### 方式二：在线插件源

1. 把这个仓库推到 GitHub；
2. 在 EchoMusic「插件管理 → 在线插件源」添加你的仓库地址（仓库根目录需有 `echo-plugins.json`）；
3. 在列表里安装「GitHub 加速器」。

> `echo-plugins.json` 里的 `repo` 和 `homepage` 目前是占位地址，推仓库前请改成你自己的。

## 使用建议

**想用自建 Xget（推荐，实测最快）**：

1. 打开「加速器」页面 →「Xget 本地加速」卡片 → 点「启用 Xget 加速」；
2. 点「自检」确认链路通（会显示 HTTP 状态、取到的字节数与速度）；
3. 进「插件管理」刷新在线插件列表，感受下载速度。

**想用公共 gh-proxy 镜像**：

1. 等自动测速跑完（首次约几秒；不可达的线路会等到超时）；
2. 看 gh-proxy 分组里哪条吞吐最高，点右侧 ⬆ 写入宿主设置；
3. 回到「设置 → 更新」，确认「GitHub 加速地址」已经变成该前缀。

Xget 分组除了桥接，也能单独用来拿加速链接（`/gh/`、`/gl/`、`/hf/` 等），不依赖本地桥。

## 排错：侧边栏入口不见了

**最常见原因：宿主把侧边栏的「插件」分组折叠了**（`sidebarSectionCollapsed.plugins = true`）。
分组折叠时，组内**所有**插件入口都会被整组收起 —— 不只是本插件，任务栏歌词等也一样看不见。
点侧边栏里「插件」那一行的折叠箭头展开即可。

加速器页面顶部的「宿主当前设置」卡片会**主动检测这个状态**：
若入口已注册但分组被折叠，会直接显示警告并提供「展开「插件」分组」一键修复按钮。

其它可能：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 卡片显示「已关闭」 | 设置里的「侧边栏入口」开关被关掉了 | 打开该开关，**立即生效**（入口改为动态增删，不需要重启） |
| 侧边栏整体收起 | 宿主设置了 `sidebarCollapsed` | 点侧边栏顶部的展开按钮 |
| 入口仍未出现 | 插件未被启用，或未重新加载 | 插件管理里刷新插件列表；确认插件处于启用状态 |

```
gh-accelerator/
├─ manifest.json   插件清单
├─ index.js        插件入口（浏览器 ESM 单文件，无构建步骤）
├─ style.css       样式，全部使用宿主主题变量
├─ icon.svg        插件图标
└─ README.md       本文件
```

- 入口是单文件 ESM，**没有任何 bare import**，Vue 运行时来自 `ctx.vue`；
- 网络请求优先用 `ctx.net.request()`（主进程 Axios，不受 CORS 限制），不可用时回退 `ctx.net.fetch()`；
- Xget 加速走 `ctx.webServer.listen(handler, { port })`，固定端口以保证宿主里存的前缀长期有效；
- 样式只引用宿主 CSS 变量（`--color-text-main`、`--color-primary`、`--border-subtle` 等），因此自动跟随深浅色与主题色；
- 写入宿主设置后立刻回读校验，避免静默失败。

## 安全边界

- 只读写 `ctx.storage` 中本插件自己的键，以及宿主的 `githubProxyUrl` 一个字段；
- 不采集、不上传任何数据；
- 所有测速请求都是对公开 GitHub 文件与公开加速线路的普通 GET；
- 启用 Xget 加速时会在 `127.0.0.1:<端口>` 开一个**只做 302 跳转**的本地 HTTP 服务：不绑定非回环地址、
  不代理内容、不读写任何本地文件，只把 URL 做一次形态换算；插件停用或宿主退出即释放端口。
